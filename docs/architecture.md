# Architecture

## Problem
Workers walk into dangerous zones, such as robot cells, press lines, or chemical
benches, without anyone noticing. Manual CCTV watching is unreliable. Violations
surface only after an incident.

## Intended users
EHS (Environment, Health & Safety) officers, plant and lab supervisors, and
integrators of PLC or andon alert systems.

## Split of responsibilities

| Layer | Runs on | Does | Implemented by |
| --- | --- | --- | --- |
| Perception | NVIDIA GPU / Jetson | decode → detect person (TensorRT) → track → OSD → metadata out | **PipeGen-generated DeepStream pipeline** |
| Decision | CPU (same device) | person filter, zone test, dedup, statistics | `src/incident_processor.py` |
| Action | CPU | JSONL incident log, MQTT alert | `src/event_logger.py`, `src/mqtt_publisher.py` |

The Python side contains **no** model, OpenCV, or inference code by design.

## PipeGen workflow (Track A)
1. **Requirement**: `pipegen_project/requirement.md`
2. **Pipeline IR**: generated by PipeGen, saved to `reports/evidence/pipegen/`
3. **Model**: a pretrained detector with a person class, selected in PipeGen
4. **Compiler**: TensorRT engine (FP16 preferred), plus the speed report
5. **Run**: generated pipeline on a camera, RTSP stream, or file, through `scripts/run_pipeline.sh`

## Metadata contract
`generic`: one JSON object per frame, per line.
```json
{"frame": 12, "timestamp": "2026-10-16T15:00:00.000Z", "source_id": 0,
 "width": 1920, "height": 1080,
 "objects": [{"label": "person", "class_id": 0, "confidence": 0.91, "track_id": 3,
              "bbox": {"left": 1200, "top": 300, "width": 150, "height": 420}}]}
```
`bbox` is in pixels (DeepStream `rect_params`: left/top/width/height). Alternatively,
`bbox_norm: [x1, y1, x2, y2]` in 0–1. `timestamp`, `source_id`, `class_id`,
`confidence` and `track_id` are optional. `width`/`height` default to
`input.frame_width/height`.

`deepstream_minimal`: DeepStream `nvmsgconv` payload-type 1, one message per line:
`{"id": "12", "@timestamp": "...", "sensorId": "cam0", "objects": ["3|1200|300|1350|720|Person"]}`,
with fields `trackId|left|top|right|bottom|label` in pixels. The frame size comes from
settings. A track ID of `-1` or `0xFFFFFFFFFFFFFFFF` means "untracked".

Both adapters follow published conventions. The real output of the generated
pipeline has **not** been seen yet; `scripts/inspect_metadata.py` reports which adapter
(if any) parses it.

## Decision logic
1. Parse each metadata line into a `Frame` (`metadata_adapters.py`). A record that
   cannot be used (invalid JSON, not an object, `objects` not a list, invalid frame
   size) is counted in `malformed_records` and skipped. An unusable object (missing,
   non-numeric or non-finite coordinates, zero or negative size, entirely outside the
   frame) is dropped, and the rest of the frame is kept. Boxes partly outside the
   frame are clamped.
2. Keep detections whose label is in `person_labels` (or whose class ID is in
   `person_class_ids`) and whose confidence is at least `min_confidence`.
3. Anchor point = **bottom-center** of the box, an approximation of floor contact. A
   person whose head overlaps the zone but whose feet are outside it is *not* an
   intrusion.
4. Zone test: point-in-rectangle on normalized coordinates, with the boundary
   counting as inside.
5. Dedup:
   - **With track IDs**: a per-(source, track, zone) state machine. An incident fires
     once after `confirm_frames` consecutive inside frames. Leaving the zone resets
     the state. A re-entry within `cooldown_seconds` is suppressed as boundary flicker.
   - **Without track IDs**: at most one incident per (source, zone) per
     `cooldown_seconds`.
   - Track state expires after `track_timeout_seconds` without sightings.
6. Emit the incident: append to JSONL (flushed per record), update stats, and publish
   to MQTT if enabled. If MQTT fails, the processor never stops logging.

## Execution flow of `incident_processor.py`
1. Load and validate `settings.yaml` (zones, labels, timing, input, MQTT). Any error
   gives exit code **2** with a one-line message.
2. Open the incident log (an error such as an unwritable directory gives exit code **1**). If
   `--mqtt` or `mqtt.enabled` is set, connect to the broker; failure only disables MQTT.
3. Read lines from a file (batch), a growing file (`--follow`, until `--idle-exit`
   seconds without data), or stdin.
4. For each line: parse (malformed → counted, skipped), filter persons, compute the
   anchor, run the zone test and dedup, and on a confirmed entry append to JSONL
   (flushed per record), update stats, and publish to MQTT.
5. Save `stats.json` every 30 frames and at the end (atomic replace), log a summary, and
   exit **0**. Ctrl+C saves the statistics before exiting.

Paths given on the command line are relative to the current directory; paths in
`settings.yaml` are relative to the project root.

## Runtime stack (from the official PipeGen v0.5.1 install guide)

```
host: Ubuntu x86-64 + NVIDIA proprietary driver + Docker + NVIDIA Container Toolkit
  └─ pipegen (GUI app, .deb)          Requirement → IR → Model → Compiler → Run
       └─ DeepStream container image  TensorRT engine build (FP32/FP16/INT8) + speed report
            └─ generated DeepStream app (run.sh)  camera/file → nvinfer → nvtracker → OSD
                 └─ JSON metadata file / MQTT ──► src/incident_processor.py (host, CPU)
```

DeepStream and TensorRT are **not** installed on the host. They come from the
container that PipeGen downloads on first launch (~12 GB). The host must provide
the GPU driver and the container runtime. Source:
`reports/evidence/environment/pipegen_official_install_guide_extract.txt`.

## How metadata reaches the processor

1. The generated app writes one JSON record per frame to a file (or MQTT topic).
2. `scripts/run_pipeline.sh` starts `incident_processor.py --follow` on
   `METADATA_PATH` **before** launching `run.sh`, so no frame is missed. It then tails
   the file as it grows, and stops `IDLE_EXIT` seconds after the last line.
3. `scripts/inspect_metadata.py` is run once on the real output to choose the adapter
   and confirm the person label, the track IDs, and the coordinate frame size.
4. Frame size: DeepStream boxes are in `nvstreammux` resolution. `generic`
   records carry `width`/`height`. For `deepstream_minimal`, `input.frame_width/height`
   must match the streammux, or the zone test is shifted.
5. Only confirmed intrusions are written to `data/incidents.jsonl`, `data/stats.json`,
   and MQTT `workplace_safety/alerts`.
